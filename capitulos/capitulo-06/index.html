Capítulo 6

Compartilhamento de recursos

Uma rede existe para que muitos usuários troquem informação, e para isso eles dividem recursos: a banda dos enlaces, os buffers dos nós e a capacidade de processar pacotes. Este capítulo mostra como dividir esses recursos de forma eficiente e justa, do acesso a um meio compartilhado ao controle de congestionamento.

Apresentação

Muitos usuários, recursos limitados

Os usuários de uma rede produzem e consomem informação que atravessa a rede. Para atendê-los, a rede usa vários tipos de recursos, e é importante saber quais são compartilhados. O primeiro e mais importante é a banda dos enlaces. Depois vêm os buffers dos nós e a capacidade de processamento de pacotes dos roteadores.

Objetivos de aprendizagem

  • Comparar as topologias em malha, barramento, estrela, anel e árvore.
  • Definir e calcular uma alocação max-min justa.
  • Explicar o congestionamento, o papel dos buffers e o colapso de congestionamento.
  • Comparar descarte (tail drop, drop from front, RED), marcação (FECN, BECN) e escalonamento round-robin.
  • Descrever o controle de acesso ao meio: TDM, FDM, ALOHA, CSMA, CSMA/CD, CSMA/CA e Token Ring.
  • Explicar por que o controle de congestionamento usa AIMD e como uma janela de congestionamento regula a taxa.

Conceito 1

Organizações físicas de uma rede local

1. Contextualização

A banda de um enlace precisa ser compartilhada em duas situações. A primeira é quando vários hosts estão ligados ao mesmo enlace físico, o caso típico das redes locais (LANs), que interligam de algumas dezenas a algumas centenas de hosts numa sala, prédio ou campus. Como ligar, por exemplo, cinco hosts para que qualquer um fale com qualquer outro?

2. Explicação

  • Malha completa (Fig. 55): um enlace entre cada par de hosts. É a organização mais confiável e de menor atraso, mas com n hosts exige n(n−1)/2 enlaces e n−1 interfaces por host, e cada host novo exige enlaces novos em todos os outros. Na prática, só é usada com poucos nós e quando a resiliência é essencial.
  • Barramento (Fig. 56): todos os hosts ligados a um meio compartilhado, em geral um cabo, por uma única interface. Um sinal enviado por um host chega a todos. Se o cabo for cortado, a rede se divide em duas. Os primeiros Ethernet usavam essa topologia.
  • Estrela (Fig. 57): um enlace entre cada host e o centro, que pode ser um equipamento que só amplifica o sinal ou um dispositivo ativo que entende as mensagens. Se o centro falha, a rede toda falha; se um enlace é cortado, só um host fica de fora. É mais fácil de operar, e o centro é um bom ponto de controle e de observação.
  • Anel (Fig. 58): cada host tem uma interface no anel, e o sinal percorre o anel num só sentido; um enlace cortado derruba a rede inteira. Em redes metropolitanas, usam-se anéis duplos, com cabos diferentes, para redundância.
  • Árvore (Fig. 59): usada quando é preciso ligar muitos clientes com baixo custo, como nas redes de TV a cabo.

3. Visualização e exploração

Escolha a organização, mude o número de hosts e corte enlaces para ver quem continua conversando.

4. Prática

Quantos enlaces uma malha completa com 10 hosts exige?

Em qual organização o corte de um único cabo afeta menos hosts?

5. Fixação

  • Malha: máximo de desempenho e resiliência, custo n(n−1)/2 enlaces.
  • Barramento e anel: uma interface por host, mas um corte afeta muitos.
  • Estrela: fácil de operar; o centro é o ponto crítico. Árvore: barata para muitos clientes.
  • Fora a malha, todas compartilham a banda: é preciso um controle de acesso ao meio.
Conceito 2

Compartilhar a banda com justiça

1. Contextualização

Antes de projetar um esquema de compartilhamento, é preciso definir o objetivo. Nas estradas, ambulâncias têm prioridade; em algumas cidades há faixas exclusivas para ônibus. Em redes de computadores, o objetivo mais popular é que o compartilhamento seja justo. Com dois hosts num enlace de 2 Mbit/s, cada um deve ficar com 1 Mbit/s. Mas e numa rede maior?

2. Explicação

Na rede da Fig. 60, A1 envia para A2, B1 para B2 e C1 para C2. Dar a mesma banda a todos (5 Mbit/s) deixa o enlace R2–R3 subutilizado. Dar 10 Mbit/s a A1–A2, 20 a C1–C2 e nada a B1–B2 é claramente injusto. A definição mais usada é a justiça max-min: uma alocação é max-min justa se é impossível dar mais banda a um fluxo sem reduzir a de outro fluxo que já tem menos.

Com a rede inteira conhecida, ela é obtida por preenchimento progressivo: todos os fluxos começam com zero e crescem juntos até um enlace congestionar; os fluxos que passam por esse enlace atingiram o máximo e saem do conjunto de candidatos; o processo continua até o conjunto ficar vazio. Na Fig. 60, A1–A2 e B1–B2 param em 5 Mbit/s quando R1–R2 satura, e C1–C2 cresce até 15 Mbit/s, quando R2–R3 satura.

3. Visualização e exploração

Ajuste a taxa de cada fluxo e veja a carga dos enlaces. Os botões mostram as duas alocações do livro e o preenchimento progressivo.

4. Prática

A alocação 5/5/5 Mbit/s da Fig. 60 é max-min justa?

5. Fixação

  • Justiça max-min: não dá para aumentar um fluxo sem diminuir outro que tem menos.
  • Preenchimento progressivo: todos crescem juntos; quem passa por um enlace saturado para.
  • Em redes grandes, a justiça é sempre um compromisso.
Conceito 3

Congestionamento, buffers e colapso

1. Contextualização

Na rede da Fig. 61, todos os enlaces levam 1000 bit/s e os pacotes têm 1000 bits. A envia um pacote por segundo para C, e tudo vai bem. Quando B também começa a transmitir, R1 recebe dois pacotes por segundo, mas só consegue repassar um para R2. O que acontece com o segundo?

2. Explicação

Se R1 tem um buffer livre, guarda o pacote até o enlace ficar livre; senão, descarta. Os buffers são o segundo recurso compartilhado: absorvem picos passageiros. Se A e B mandam, em média, três pacotes a cada dez segundos (0,6 pacote/s, abaixo da capacidade), mas começam juntos, R1 precisa absorver uma rajada. Uma rede está congestionada quando a soma da demanda dos hosts é maior que a capacidade da rede. Os operadores aceitam congestionamentos passageiros (segundos ou minutos), mas querem evitar os que duram dias ou meses.

Buffers maiores evitam descartes, mas aumentam o atraso. E buffers enormes não resolvem: se A e B mandam mil pacotes cada com Go-Back-N, a fila cresce, o atraso cresce, os temporizadores expiram, os hosts retransmitem, a fila cresce ainda mais… No fim, o enlace R1–R2 transporta muitas cópias dos mesmos pacotes. É o colapso de congestionamento (RFC 896): a rede carrega pacotes sem entregar dados úteis.

Nota do livro
O colapso não é só teoria. Em outubro de 1986, a vazão entre o Lawrence Berkeley Laboratory e a Universidade da Califórnia em Berkeley caiu de 32 kbit/s para 40 bit/s, uma queda de mil vezes, segundo o relato de Van Jacobson citado pelo livro (pág. 85 do PDF). Esse trabalho levou às técnicas de controle de congestionamento que permitiram à Internet crescer.

O terceiro recurso é a capacidade de processamento: para encaminhar, o roteador consulta a tabela de encaminhamento, o que gasta ciclos de CPU e acessos à memória. Por isso o desempenho de um roteador tem duas medidas: a capacidade em bits por segundo, que depende das interfaces e da interconexão interna e é atingida com pacotes grandes, e o desempenho de consulta em pacotes por segundo, que limita o roteador com pacotes pequenos.

Quando a fila cresce, o atraso cresce (Fig. 62). Com ocupação baixa mas não nula, a vazão aumenta; com o buffer quase cheio, a vazão para de crescer e pode cair, por causa das retransmissões desnecessárias. Um bom ponto de operação é uma ocupação baixa: boa utilização e pouco atraso.

3. Visualização e exploração

A e B começam uma rajada ao mesmo tempo. Ajuste a rajada e o buffer de R1 e acompanhe segundo a segundo.

4. Prática

Por que buffers infinitos em R1 não evitam o colapso de congestionamento?

Um roteador encaminha pacotes mínimos. Em que medida o desempenho dele costuma ficar limitado?

5. Fixação

  • Recursos compartilhados: banda, buffers e capacidade de processamento.
  • Congestionamento: demanda maior que a capacidade; buffers absorvem rajadas curtas.
  • Buffers demais aumentam o atraso e não evitam o colapso de congestionamento.
Conceito 4

Como a rede avisa que está congestionada

1. Contextualização

Os hosts conseguem adaptar a demanda ao estado da rede, desde que percebam o congestionamento. Uma forma é medir o atraso (o RTT cresce com a fila), mas em enlaces rápidos a variação pode se confundir com flutuações normais. Que outros sinais a rede pode dar?

2. Explicação

Descartar pacotes é a segunda reação de um nó. As filas são FIFO, para manter a ordem, e um mecanismo de descarte responde a duas perguntas: quando descartar (com o buffer cheio, ou antes, quando a ocupação cresce demais) e qual pacote descartar.

  • Tail drop: com o buffer cheio, descarta o pacote que chega. É simples e o mais usado, mas mantém os buffers cheios (atraso para aplicações de tempo real) e é cego: pode descartar o pacote de um fluxo interativo enquanto o buffer está ocupado por transferências grandes.
  • Drop from front: descarta o pacote da cabeça da fila, que já esperou muito; o host percebe a perda mais cedo.
  • Descarte probabilístico, como o RED (Random Early Discard): mede a ocupação média e, quando ela fica alta, descarta com certa probabilidade. Assim, os descartes atingem os fluxos em proporção à banda que usam.

Descartar não é o ideal, porque o pacote descartado já gastou recursos nos nós anteriores. A rede também pode marcar pacotes:

  • FECN (Forward Explicit Congestion Notification), em redes de datagramas: um bit do cabeçalho é ligado ao passar por um nó congestionado; o destino mede a fração de pacotes marcados e avisa o emissor. O host percebe o congestionamento sem depender de perdas.
  • BECN (Backward), em redes de circuitos virtuais: o nó marca os pacotes do caminho de volta (por exemplo, as confirmações), o que avisa o emissor mais rápido.
  • Pacotes de controle enviados à origem: usados em redes pequenas, evitados nas grandes, porque aumentam a carga justo no congestionamento e roteadores são lentos para criar pacotes.

3. Visualização e exploração

4. Prática

Qual política pode descartar o pacote de um fluxo interativo só porque o buffer está cheio de pacotes de uma transferência?

Em circuitos virtuais, qual técnica avisa o emissor mais rápido?

5. Fixação

  • Sinais de congestionamento: atraso, descarte, marcação e pacotes de controle.
  • Tail drop é simples e cego; RED descarta cedo e em proporção à banda.
  • FECN marca na ida; BECN marca na volta e avisa mais rápido.
Conceito 5

Escalonamento round-robin

1. Contextualização

Descartar e marcar não são as únicas reações possíveis. Um roteador também pode atrasar seletivamente os pacotes de alguns fluxos. Se o objetivo é dividir a banda de saída com justiça, como organizar os buffers?

2. Explicação

Uma possibilidade é ter uma fila por fluxo (digamos N filas): cada pacote que chega vai para o fim da fila do seu fluxo. Um escalonador é executado a cada oportunidade de transmissão e escolhe de qual fila sai o próximo pacote. O mais simples é o round-robin (Fig. 63), que serve as filas em rodízio. Se todos os fluxos usam pacotes do mesmo tamanho, a banda é dividida com justiça; caso contrário, ele favorece os fluxos de pacotes maiores. Há extensões que dividem com justiça mesmo com tamanhos variáveis, fora do escopo do livro. 

# N filas
# variável de estado: next_queue
next_queue = 0
while True:
    if isEmpty(buffer):
        wait()                      # espera o próximo pacote
    if not(isEmpty(queue[next_queue])):
        p = remove_packet(queue[next_queue])
        send(p)                     # envia o pacote da cabeça da fila
    next_queue = (next_queue + 1) % N

Pseudocódigo do escalonador round-robin (livro, pág. 88 do PDF).

3. Visualização e exploração

4. Prática

Dois fluxos com filas cheias: um usa pacotes de 1500 bytes e o outro, de 500. Quem leva mais banda com round-robin?

5. Fixação

  • Uma fila por fluxo e um escalonador que escolhe a próxima a transmitir.
  • Round-robin: justo em pacotes; em bytes, só se os tamanhos forem iguais.
Conceito 6

Distribuindo a carga pela rede

1. Contextualização

Além de agir em cada nó, dá para desviar tráfego dos enlaces carregados, limitar quem entra na rede ou espalhar a carga entre várias fontes. Como servir um arquivo popular, como a imagem de uma distribuição Linux, a milhões de usuários?

2. Explicação

  • Pesos dinâmicos: os primeiros algoritmos de roteamento mediam o atraso e mudavam os pesos dos enlaces. Na prática, isso podia causar oscilações sem reduzir o congestionamento. Hoje, contra congestionamentos longos (horas ou dias), mede-se a demanda e escolhem-se pesos que minimizem a carga máxima; se não bastar, a rede precisa de enlaces novos ou mais rápidos, o que pode levar meses.
  • Controle de admissão: em redes de circuitos virtuais, a rede só cria um circuito se houver recursos; senão, recusa. É o que faz o sinal de ocupado da rede telefônica. Em redes de datagramas, isso não se aplica facilmente, porque um host pode mandar qualquer pacote a qualquer destino a qualquer hora.
  • Serviço de nomes: o arquivo fica em vários servidores, e o serviço de nomes devolve endereços diferentes a clientes diferentes (Capítulo 5).
  • BitTorrent: o arquivo é dividido em blocos de tamanho fixo, e metadados indicam quais hosts guardam cada bloco. O cliente baixa os blocos em qualquer ordem, de hosts diferentes e em paralelo, e passa a oferecer os blocos que já tem. Assim, quanto mais popular o arquivo, mais fontes ele tem.

3. Visualização e exploração

4. Prática

Por que o BitTorrent aguenta bem um arquivo muito popular?

5. Fixação

  • Contra congestionamento longo: ajustar pesos ou aumentar a rede.
  • Controle de admissão: natural em circuitos virtuais, difícil em datagramas.
  • Espalhar a carga: vários servidores via nomes, ou blocos trocados entre clientes (BitTorrent).
Conceito 7

Controle de acesso ao meio: alocação estática

1. Contextualização

Numa LAN, se dois dispositivos transmitem ao mesmo tempo, os sinais se sobrepõem e o receptor não decodifica nenhum dos quadros: é uma colisão, a principal causa de erros em LANs com fio. Todas as tecnologias de LAN usam um algoritmo de controle de acesso ao meio (MAC) para reduzir ou evitar colisões.

2. Explicação

Há duas famílias de algoritmos MAC:

  • Determinísticos ou pessimistas: evitam toda colisão, garantindo que só um dispositivo transmita por vez, ao custo de algum trabalho para coordenar os dispositivos.
  • Estocásticos ou otimistas: aceitam colisões como parte da operação e tentam minimizá-las; costumam ser mais fáceis de implementar.

A solução determinística mais simples é a alocação estática: com N dispositivos numa LAN de b Mbit/s, cada um recebe b/N Mbit/s.

  • FDM (Frequency Division Multiplexing): cada dispositivo usa uma frequência diferente, então não há colisões. Nas fibras ópticas, a variante WDM dá um comprimento de onda a cada dispositivo. O espectro de rádio (de cerca de 3 kHz a 300 GHz) é dividido assim entre rádio, TV, celulares, satélites etc.
  • TDM (Time Division Multiplexing): o tempo é dividido em quadros de 125 µs, e cada conversa tem sempre a mesma posição em cada quadro (Fig. 64). Uma conversa telefônica é um sinal de 64 kbit/s, ou seja, um byte a cada 125 µs; na Europa, trinta conversas são multiplexadas numa linha E1 de 2 Mbit/s.

Complemento
A linha E1 tem 2,048 Mbit/s divididos em 32 intervalos de 64 kbit/s: 30 para voz e 2 para sincronização e sinalização (Wikipedia: E-carrier).

TDM e FDM servem bem a conversas de taxa fixa. Computadores, porém, têm comportamento liga-desliga: enviam o mais rápido possível durante um período curto e ficam calados por muito tempo. Com alocação estática, cada computador ligado só usaria 1/N da banda, mesmo com os outros calados. Os algoritmos MAC dinâmicos, a seguir, resolvem isso.

3. Visualização e exploração

4. Prática

Num TDM estático com 4 computadores, quanto um computador consegue usar quando só ele tem dados?

5. Fixação

  • Colisão: duas transmissões simultâneas que o receptor não decodifica.
  • MAC determinístico evita colisões; MAC estocástico as minimiza.
  • FDM/WDM e TDM dividem frequência ou tempo de forma fixa: ótimos para voz, ineficientes para tráfego liga-desliga.
Conceito 8

ALOHA e ALOHA com slots

1. Contextualização

Nos anos 1960, a Universidade do Havaí quis ligar terminais distantes a um computador central sem usar linhas telefônicas. Criou a primeira tecnologia de rádio por pacotes, a ALOHANet, e mostrou que computadores podem ser interligados por rádio.

2. Explicação

Os quadros tinham tamanho fixo (704 bits: 80 caracteres de 8 bits, controle e paridade), e havia dois canais na faixa de 400 MHz: um do computador central para todos os terminais e outro compartilhado pelos terminais. O central conferia a paridade e confirmava cada quadro correto no seu canal; o terminal retransmitia os quadros sem confirmação. Retransmitir logo após um timeout fixo sincronizaria terminais que colidiram, por isso cada terminal espera um tempo aleatório antes de tentar de novo. 

# ALOHA
N = 1
while N <= max:
    send(frame)
    wait(ack_on_return_channel or timeout)
    if ack_on_return_channel:
        break                       # transmissão bem-sucedida
    else:                           # timeout
        wait(random_time)
        N = N + 1
else:
    pass                            # tentativas demais

O ALOHA funciona bem com o canal pouco carregado, mas a utilização máxima é baixa e, acima dela, a rede fica instável e colapsa com as retransmissões que colidem. O ALOHA com slots divide o tempo em intervalos do tamanho de um quadro e só deixa transmitir no início de cada intervalo (o relógio pode vir do computador central). Essa mudança simples dobra a utilização máxima.

Divergência no livro
O livro dá dois valores para o máximo do ALOHA puro: 0,186 (pág. 92 do PDF) e 18,4% (pág. 93). O correto é 1/(2e) ≈ 0,184, atingido com carga G = 0,5. Para o ALOHA com slots, o livro dá 36,6% (pág. 93); o máximo é 1/e ≈ 0,368, com G = 1. O bloco de código 4, abaixo, faz as contas.

3. Visualização e exploração

G é a carga oferecida: quantos quadros, contando retransmissões, tentam usar o canal por tempo de quadro.

4. Prática

Por que o ALOHA com slots dobra a utilização máxima?

5. Fixação

  • ALOHA: transmite quando quer; sem confirmação, espera um tempo aleatório e retransmite.
  • Máximo de ≈ 18,4% (puro) e ≈ 36,8% (com slots); com carga alta, colapsa.
  • Variantes do ALOHA ainda aparecem em redes sem fio.
Conceito 9

CSMA e CSMA/CD

1. Contextualização

O ALOHA só serve para redes pouco carregadas. Projetar uma rede para baixa utilização é possível, mas caro. Uma melhoria óbvia: antes de transmitir, escutar o canal.

2. Explicação

No CSMA (Carrier Sense Multiple Access), o nó só transmite com o canal livre. No CSMA persistente, ele espera o canal ficar livre e transmite na hora; se dois nós esperavam, os dois transmitem juntos e colidem. No CSMA não persistente, quem encontra o canal ocupado espera um tempo aleatório antes de escutar de novo, o que evita essa sincronização e melhora a utilização, com um pouco mais de espera quando a rede está vazia. Sob as hipóteses da análise citada pelo livro, o CSMA persistente chega a 52,9% da capacidade e o não persistente, a 81,5%.

Num cabo, o sinal se propaga a cerca de 200 000 km/s: num cabo de 1 km, leva 5 µs de uma ponta à outra. Hosts diferentes recebem o início de um quadro em instantes diferentes (Fig. 65), e dois hosts podem achar o canal livre e transmitir quase juntos (Fig. 66). Numa rede com fio, o host consegue detectar a colisão enquanto transmite, comparando o sinal que envia com o que sente no cabo. É a base do CSMA/CD (Collision Detection), usado no Ethernet: ao detectar uma colisão, o host para imediatamente e envia um sinal de jamming para que todos a percebam.

  • Pior caso (Fig. 67): com τ o tempo de propagação de ponta a ponta, B começa pouco antes de τ e A só detecta a colisão perto de 2τ. Uma colisão só pode acontecer nos primeiros 2τ de uma transmissão.
  • Sem confirmações: como colisões são quase a única causa de erro numa rede com fio, o CSMA/CD dispensa as confirmações: se não houve colisão, o quadro é dado como entregue.
  • Quadro mínimo (Fig. 68): para isso funcionar, o host precisa transmitir por pelo menos 2τ, senão termina antes de perceber a colisão. Isso impõe um tamanho mínimo de quadro; no Ethernet, 2τ é o slot time.
  • Backoff exponencial binário: depois da N-ésima colisão, o host espera r slot times, com r sorteado entre 0 e 2k−1 e k = min(10, N). Com dois hosts, a primeira tentativa evita nova colisão em 50% dos casos, e o intervalo dobra a cada colisão para se adaptar a redes mais carregadas.

Depois de cada quadro, o host espera um curto intervalo entre quadros, o que dá chance aos outros e contribui para a justiça. Mesmo assim, o CSMA/CD nem sempre é justo: um cliente que só manda confirmações pode sofrer colisões seguidas com um servidor que envia quadros longos.

3. Visualização e exploração

A fica numa ponta do cabo e B na outra. Escolha quando B começa e a duração dos quadros.

4. Prática

Por que o CSMA/CD exige um tamanho mínimo de quadro?

Depois da segunda colisão de um quadro, quanto o host pode esperar?

5. Fixação

  • CSMA: escuta antes; o não persistente espera um tempo aleatório e usa melhor o canal.
  • CSMA/CD: detecta a colisão enquanto transmite e para; não usa confirmações.
  • Quadro mínimo de 2τ (slot time) e backoff exponencial binário.
Conceito 10

CSMA/CA e a estação escondida

1. Contextualização

Numa rede sem fio, como o WiFi, um dispositivo não consegue detectar uma colisão enquanto transmite. Além disso, o sinal de rádio não se propaga igual em todas as direções. O que muda no acesso ao meio?

2. Explicação

O CSMA/CA (Collision Avoidance) também escuta o canal, mas tenta evitar colisões ajustando bem os temporizadores. Usa confirmações, com número de sequência (contra duplicatas) e CRC (contra erros):

  • SIFS: o pequeno intervalo entre receber um quadro e enviar a confirmação, o tempo de mudar o rádio de recepção para transmissão.
  • DIFS: para transmitir, o canal precisa estar livre por pelo menos esse tempo, se o último quadro recebido estava correto; EIFS, se estava corrompido (sinal de colisões). Como SIFS < DIFS < EIFS, ninguém transmite no meio de uma confirmação (Fig. 69).
  • Backoff: cada dispositivo sorteia um atraso aleatório, cujo intervalo cresce exponencialmente com as retransmissões. O intervalo inicial, de 0 a 7 slot times, é sete vezes maior que no CSMA/CD, porque as colisões não são detectadas e podem estragar o quadro inteiro. O temporizador fica congelado enquanto o canal está ocupado e recomeça quando ele fica livre (Fig. 71).

A estação escondida (Fig. 72): dois dispositivos separados por uma parede (ou um morro, ou um caminhão) não se ouvem, mas ambos alcançam um terceiro. Para isso, o CSMA/CA permite reservar o canal com dois quadros curtos de controle: o emissor envia um RTS (Request To Send) com a duração da reserva, e o destino responde, após um SIFS, com um CTS (Clear To Send) com a mesma duração. Quem ouve qualquer um dos dois adia o acesso até o fim da reserva (Fig. 73). Como RTS e CTS custam tempo, a reserva é útil quando as colisões são frequentes; alguns dispositivos só a ligam depois de erros de transmissão.

3. Visualização e exploração

4. Prática

Na estação escondida, como C fica sabendo da reserva de A?

Por que o backoff inicial do CSMA/CA é maior que o do CSMA/CD?

5. Fixação

  • CSMA/CA: escuta, espera DIFS (ou EIFS) e um backoff aleatório; confirma após SIFS.
  • O backoff congela com o canal ocupado.
  • RTS/CTS reserva o canal e resolve a estação escondida.
Conceito 11

Acesso determinístico: Token Ring

1. Contextualização

Nos anos 1970 e 1980, houve um grande debate sobre o melhor MAC para LANs. Os algoritmos otimistas eram fáceis de implementar e aguentavam carga, mas nenhum garantia entregar um quadro dentro de um atraso máximo, e algumas aplicações precisam de atrasos previsíveis. O comitê IEEE 802 acabou criando três grupos: o 802.3 para CSMA/CD e, entre os defensores das fichas (tokens), o 802.4 (Token Bus, defendido pela indústria liderada pela General Motors) e o 802.5 (Token Ring, defendido pela IBM). Essas tecnologias quase não são mais usadas, mas os princípios continuam importantes.

2. Explicação

Um Token Ring é um conjunto de estações num anel unidirecional (Fig. 74), por onde circulam dois tipos de quadro: tokens e quadros de dados. O token é a autorização para transmitir. Para enviar, a estação captura o token, retirando-o do anel; como só uma estação o tem, não há colisões. Depois de transmitir, ela retira o próprio quadro do anel e devolve o token.

  • A interface de cada estação faz parte do anel e repassa o sinal mesmo com a estação desligada. Em modo de escuta, ela introduz um atraso de um bit e regenera o sinal.
  • O token tem 24 bits (Fig. 75): Starting Delimiter, Access Control (com o bit Token) e Ending Delimiter.
  • Para capturar o token, a estação espera o quarto bit do Access Control: se o bit Token está ligado, ela o zera no seu buffer de um bit. O começo do token vira o começo de um quadro de dados (Fig. 76), e a estação passa a transmitir. O atraso de um bit é o que permite essa captura.
  • Um quadro passa por todas as estações; o destino reconhece o próprio endereço e o copia. A estação fica em modo de transmissão até receber o último bit do próprio quadro, para que ele não fique no anel para sempre.
  • O Monitor, escolhido por eleição, insere um atraso de pelo menos 24 bits (para o token caber no anel), envia o primeiro token e verifica se ele passa regularmente. Como uma estação pode reter o token por no máximo o Token Holding Time (THT, pouco menos de 10 ms), com N estações o token precisa passar pelo Monitor pelo menos a cada N × THT. Se não passar, o Monitor reinicializa o anel e envia um token novo. Se o Monitor falhar, outra estação é eleita.

3. Visualização e exploração

4. Prática

Por que não há colisões num Token Ring que funciona normalmente?

O que o Monitor faz quando o token não passa por ele dentro do tempo esperado?

5. Fixação

  • Só quem tem o token transmite: acesso determinístico, sem colisões.
  • Captura pelo bit Token, graças ao atraso de um bit por estação.
  • O Monitor mantém o token circulando e recupera o anel em caso de falha.
Conceito 12

Controle de congestionamento

1. Contextualização

As redes misturam enlaces de dezenas de kbit/s a centenas de Gbit/s, e qualquer host deve conseguir trocar segmentos com um servidor rápido. Na Fig. 77, o servidor A, num enlace de 10 Mbit/s, envia para C por um caminho com um enlace de 2 Mbit/s. Como A descobre a que taxa pode enviar?

2. Explicação

Autorregulação (self clocking, Fig. 78): com uma janela de três segmentos, A envia três segmentos seguidos e para. O buffer de R1 os guarda e os repassa a 2 Mbit/s; cada confirmação de C libera um segmento novo. Depois da primeira janela, A envia um segmento por confirmação: as confirmações funcionam como um relógio que ajusta A à taxa do destino, desde que haja buffers.

Com muitos emissores (Fig. 79), a fila cresce e o RTT também. Com segmentos de 10 000 bits, cada um leva 1 ms no enlace de 10 Mbit/s e 5 ms no de 2 Mbit/s: o RTT, sem propagação, é cerca de 6 ms; com 100 segmentos na fila, passa a 1 + 100 × 5 + 5 ms. Com Go-Back-N, os temporizadores expiram, janelas inteiras são retransmitidas e a fila cresce mais: é o colapso de congestionamento, que aconteceu várias vezes na Internet no fim dos anos 1980. Para evitá-lo, os hosts precisam regular a taxa. Na Internet, isso é feito na camada de transporte. Com n hosts dividindo um gargalo, o esquema deve atingir três objetivos:

  1. evitar congestionamento: a soma das taxas não passa da banda do gargalo;
  2. ser eficiente: a soma das taxas fica perto da banda do gargalo, um recurso caro;
  3. ser justo: em geral, max-min justo; com um único gargalo, todos recebem a mesma taxa.

No plano de alocações (Fig. 81), o eixo x é a taxa de B e o eixo y, a de A, com um gargalo de 2 Mbit/s. A reta x + y = 2 é a reta de eficiência, e a diagonal x = y, a reta de justiça. (0,7; 0,7) é justo mas ineficiente; (1,5; 0,5) é eficiente mas injusto; (1; 1) é as duas coisas.

Com realimentação binária, o host só sabe se a rede está congestionada ou não. Uma adaptação linear tem a forma r(t+1) = α + β·r(t), com constantes diferentes para cada situação. A análise de Chiu e Jain mostra que, para ser justa e eficiente, ela precisa ser AIMD: aumento aditivo sem congestionamento (α > 0, β = 1) e diminuição multiplicativa com congestionamento (α = 0, β < 1). 

# Additive Increase Multiplicative Decrease
if congestion:
    rate = rate * betaC     # diminuição multiplicativa, betaC < 1
else:
    rate = rate + alphaN    # aumento aditivo, alphaN > 0

A realimentação pode ser implícita, como no TCP, que trata perdas como sinal de congestionamento (verdade em redes com fio, nem sempre nas sem fio), ou explícita, como no DECbit: roteadores congestionados ligam um bit nos pacotes, e o destino devolve essa informação nas confirmações (para IP, RFC 3168).

Com janelas: ajustar a taxa diretamente exige temporizadores finos; protocolos como o TCP ajustam a janela. Na Fig. 83, os enlaces de acesso têm 1 Mbit/s, o gargalo R1–R2 tem 500 kbit/s e os pacotes têm 1000 bits. Com janela de 1 segmento, A envia a 250 kbit/s (Fig. 84); com 2, já atinge os 500 kbit/s do gargalo (Fig. 85); com 4, continua em 500 kbit/s, mas dois pacotes esperam no buffer de R1 e o RTT cresce (Fig. 86). Daí a janela de congestionamento cwin: a janela de envio fica limitada a min(swin, cwin), além da janela anunciada pelo receptor. No aumento aditivo, cwin cresce um segmento por RTT (cwin += 1/cwin a cada confirmação nova); na diminuição multiplicativa, cai pela metade quando há congestionamento.

3. Visualização e exploração

Dois hosts partem de uma alocação injusta. Compare AIMD e AIAD no plano de alocações.

Agora a janela de congestionamento de um host com realimentação do tipo DECbit: o roteador marca os pacotes quando há fila.

4. Prática

Qual adaptação leva dois hosts com taxas diferentes a uma alocação justa e eficiente?

Na Fig. 83, com janela de 4 segmentos, a que taxa A envia?

5. Fixação

  • Self clocking: as confirmações ditam o ritmo do emissor.
  • Objetivos: evitar congestionamento, ser eficiente e ser justo.
  • Com realimentação binária, só o AIMD converge para justo e eficiente.
  • Na prática, a janela de congestionamento faz o papel da taxa: min(swin, cwin).
Pratique

Exercícios graduados

  1. Aquecimento: quantos enlaces e interfaces por host exigem uma malha e uma estrela com 8 hosts?
    Ver solução

    Malha: 8 × 7 / 2 = 28 enlaces e 7 interfaces por host. Estrela: 8 enlaces e 1 interface por host.

  2. Aquecimento: num cabo de 2 km, com o sinal a 200 000 km/s, quanto vale τ? E o slot time?
    Ver solução

    τ = 2 km / 200 000 km/s = 10 µs, e o slot time é 2τ = 20 µs.

  3. Intermediário: nesse cabo, a 10 Mbit/s, qual é o menor quadro que garante a detecção de colisões?
    Ver solução

    O quadro precisa durar 20 µs: 10 × 106 bit/s × 20 × 10−6 s = 200 bits (25 bytes).

  4. Intermediário: no exemplo da Fig. 79, qual é o RTT com 100 segmentos de 10 000 bits na fila?
    Ver solução

    1 + 100 × 5 + 5 = 506 ms, contra cerca de 6 ms com a fila vazia.

  5. Intermediário: no ALOHA com slots, qual é a fração de slots vazios com G = 1?
    Ver solução

    A probabilidade de nenhum quadro num slot é e−G = e−1 ≈ 36,8%; outros 36,8% têm exatamente um quadro (sucesso) e os 26,4% restantes, colisões.

  6. Desafio: dois hosts com AIMD (α = 0,1 Mbit/s, β = 0,5) dividem um gargalo de 2 Mbit/s e partem de A = 0,2 e B = 1,4. Depois do primeiro congestionamento, qual é a diferença entre as taxas?
    Ver solução

    Os dois crescem juntos e a diferença fica em 1,2. A soma vai de 1,6 para 1,8 e 2,0 (ainda não passa de 2) e, no terceiro aumento, chega a 0,5 + 1,7 = 2,2: congestionado. A diminuição multiplicativa leva a 0,25 e 0,85, e a diferença cai de 1,2 para 0,6. Cada congestionamento corta a diferença pela metade.

2. Alocação max-min por preenchimento progressivo

def max_min(capacidade, fluxos, passo=0.5):
    """Preenchimento progressivo: todos os fluxos crescem juntos até saturar um enlace."""
    taxa = {f: 0.0 for f in fluxos}
    candidatos = set(fluxos)
    while candidatos:
        for f in candidatos:
            taxa[f] += passo
        carga = {e: sum(taxa[f] for f in fluxos if e in fluxos[f]) for e in capacidade}
        cheios = {e for e in capacidade if carga[e] >= capacidade[e] - 1e-9}
        for f in list(candidatos):
            if fluxos[f] & cheios:          # o fluxo passa por um enlace saturado
                candidatos.remove(f)
    return taxa

# Rede da Fig. 60 do livro
capacidade = {"R1-R2": 10, "R2-R3": 20}
fluxos = {"A1-A2": {"R1-R2"}, "B1-B2": {"R1-R2", "R2-R3"}, "C1-C2": {"R2-R3"}}
for f, t in max_min(capacidade, fluxos).items():
    print(f"{f}: {t:g} Mbit/s")

3. O escalonador round-robin do livro

from collections import deque

def round_robin(filas, tempo_total):
    """Pseudocódigo do livro (pág. 88): serve as filas em rodízio, um pacote por vez."""
    n = len(filas)
    enviados = [0] * n            # bytes enviados por fluxo
    proxima, tempo = 0, 0
    while tempo < tempo_total and any(filas):
        if filas[proxima]:
            p = filas[proxima].popleft()      # tamanho do pacote em bytes
            enviados[proxima] += p
            tempo += p                        # o enlace leva tempo proporcional ao tamanho
        proxima = (proxima + 1) % n
    return enviados

tamanhos = [1000, 1000, 1500, 500, 1000]
filas = [deque([t] * 1000) for t in tamanhos]   # filas sempre cheias
enviados = round_robin(filas, 100_000)
total = sum(enviados)
for i, (t, b) in enumerate(zip(tamanhos, enviados), 1):
    print(f"fluxo {i} ({t:>4} bytes): {b:>6} bytes = {100 * b / total:4.1f}% da banda")

4. A utilização do ALOHA

import math, random

def puro(G):
    return G * math.exp(-2 * G)

def com_slots(G):
    return G * math.exp(-G)

for G in (0.25, 0.5, 1.0, 2.0):
    print(f"G = {G:4}: ALOHA puro S = {puro(G):.3f} | com slots S = {com_slots(G):.3f}")
print(f"Máximos: puro 1/(2e) = {1 / (2 * math.e):.3f}; com slots 1/e = {1 / math.e:.3f}")

# Conferência por simulação: ALOHA com slots, chegadas de Poisson com média G por slot
def simula_slots(G, slots, rnd):
    sucesso = 0
    for _ in range(slots):
        # número de quadros no slot: conta eventos de Poisson com média G
        k, p, limite = 0, 1.0, math.exp(-G)
        while True:
            p *= rnd.random()
            if p < limite:
                break
            k += 1
        sucesso += (k == 1)
    return sucesso / slots

rnd = random.Random(1)
print(f"Simulação com slots, G = 1: S = {simula_slots(1.0, 100_000, rnd):.3f}")

5. Backoff exponencial binário

import random

def disputa(rnd, max_tentativas=16):
    """Dois hosts colidiram. Devolve quantas colisões houve até um deles transmitir sozinho."""
    for n in range(1, max_tentativas + 1):
        k = min(10, n)
        a = rnd.randint(0, 2 ** k - 1)     # r = random(0, 2**k - 1), como no pseudocódigo do livro
        b = rnd.randint(0, 2 ** k - 1)
        if a != b:
            return n
    return None

rnd = random.Random(42)
resultados = [disputa(rnd) for _ in range(10_000)]
media = sum(resultados) / len(resultados)
print(f"Colisões em média até resolver: {media:.2f}")
for n in range(1, 5):
    print(f"resolvida na colisão {n}: {resultados.count(n) / len(resultados):.1%}")

6. AIMD × AIAD com dois fluxos

def simula(alg, a=0.1, b=1.6, capacidade=2.0, passos=60):
    """Dois hosts com a mesma realimentação binária: congestionado se a + b > capacidade."""
    for _ in range(passos):
        if a + b > capacidade:
            if alg == "AIMD":
                a, b = a * 0.5, b * 0.5        # diminuição multiplicativa
            else:
                a, b = max(0, a - 0.3), max(0, b - 0.3)   # diminuição aditiva
        else:
            a, b = a + 0.1, b + 0.1            # aumento aditivo
    return a, b

for alg in ("AIMD", "AIAD"):
    a, b = simula(alg)
    print(f"{alg}: A = {a:.2f}, B = {b:.2f}, diferença = {abs(a - b):.2f} Mbit/s")
