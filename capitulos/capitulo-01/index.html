Fundamentos

O que é informação, afinal?

Vídeos, fotos, músicas e páginas da Web têm algo em comum por baixo do capô: tudo é guardado e movido pela rede como dados digitais, isto é, longas sequências do menor tipo de informação que existe — o bit, que só pode valer 0 ou 1.

Um bit sozinho não diz muita coisa. O interessante acontece quando vários bits são agrupados: 8 bits formam 1 byte, e combinações de bytes conseguem representar letras, números, pixels de uma imagem ou instruções de um programa. A tabela ASCII, por exemplo, define que a letra "A" deve ser transmitida como a sequência 01000001.

🧪 Experimente: texto → binário

Digite algo e veja os bytes UTF-8 usados para codificar o texto. ASCII representa apenas 128 caracteres; UTF-8 mantém esses mesmos bytes para eles e usa de 2 a 4 bytes para outros caracteres.

O ponto principal não é decorar quantos bits cada tipo de arquivo usa, mas perceber a escala do problema: uma comunicação comum pela Internet envolve uma quantidade gigantesca de bits em trânsito, o tempo todo, entre milhões de pares de computadores. Isso leva à pergunta natural: se tudo é bit, como esses bits não "engarrafam" os cabos do mundo inteiro?

Analogia

A Cachoeira Perpétua

Uma analogia, não uma arquitetura formal. A “Cachoeira Perpétua” é uma representação didática para visualizar como o tráfego pode atravessar diferentes escalas da infraestrutura de rede. Os termos Topo, Queda, Base e Leito não são camadas oficiais da Internet nem descrevem uma topologia obrigatória. Na prática, os caminhos dos dados variam conforme a tecnologia, o provedor e a topologia da rede.

Para responder a essa pergunta, é útil parar de olhar para um bit isolado e observar a infraestrutura que carrega bilhões deles ao mesmo tempo. Uma boa forma de visualizar essa estrutura é imaginar uma cachoeira: a água (os dados) começa concentrada no topo e, à medida que desce, vai se espalhando por caminhos cada vez menores, até chegar calma ao leito do rio — o seu dispositivo.

Topo

Cabos submarinos ligam continentes usando sinais ópticos e DWDM, multiplicando a capacidade de uma única fibra.

Queda

Backbones terrestres levam o tráfego por milhares de quilômetros dentro de um país.

Base

Redes metropolitanas distribuem o tráfego entre cidades e bairros.

Leito

A rede de acesso entrega os bits ao dispositivo final do usuário.

Aprofundando

Por dentro da camada física

Antes de dois hosts trocarem qualquer coisa, eles precisam de um meio físico compartilhado: cabo elétrico, fibra óptica ou rádio. A camada física é a responsável por transformar bits (0s e 1s) em sinais que realmente viajam por esse meio — tensão elétrica, pulsos de luz ou ondas eletromagnéticas.

Um esquema simples ilustra o princípio: para transmitir 1000 bits por segundo em um fio elétrico, os dois hosts podem combinar que +5V durante 1 milissegundo representa o bit 1, e -5V representa o bit 0. O receptor apenas mede a tensão a cada milissegundo e decodifica o bit correspondente.

⚡ Interferência eletromagnética

Tempestades, cabos vizinhos e antenas próximas podem alterar a tensão medida pelo receptor. O bit enviado como 0 pode chegar como 1 — daí a necessidade de mecanismos de detecção de erro.

🕓 Desalinhamento de relógios

Emissor e receptor usam relógios independentes. Uma diferença mínima de frequência entre eles faz bits "sumirem" ou "aparecerem" durante a transmissão, mesmo sem interferência externa.

Por isso, a camada física é tratada como um serviço imperfeito: ela pode alterar o valor de um bit, entregar bits a mais ou entregar bits a menos do que os enviados. Todo o restante da pilha de protocolos existe, em boa parte, para lidar com essas imperfeições.

Camada de enlace

Enquadramento: separando os bits em quadros

As camadas de rede não trabalham todas com a mesma unidade de dados. Na camada de enlace, os dados são organizados em blocos chamados quadros (frames). O problema do enquadramento é: como o receptor consegue identificar onde um quadro começa e onde termina dentro do fluxo de bits?

Uma técnica clássica é a inserção de bits (bit stuffing): reserva-se a sequência 01111110 como marcador de início/fim de quadro. Para garantir que essa sequência nunca apareça "por acidente" dentro dos dados, o transmissor insere um bit 0 extra sempre que encontra cinco 1s consecutivos no quadro. O receptor faz o processo inverso, removendo os bits inseridos.

Implementações em software costumam preferir manipular caracteres em vez de bits isolados: a técnica equivalente é o character stuffing, que usa os caracteres de controle ASCII DLE STX para marcar o início e DLE ETX para marcar o fim de um quadro, duplicando qualquer DLE que apareça nos dados.

Camada de enlace

Entrega confiável sobre um enlace imperfeito

Mesmo com enquadramento correto, quadros ainda podem ser corrompidos ou perdidos. A solução mais simples é o Protocolo do Bit Alternante (Alternating Bit Protocol — ABP): cada quadro de dados carrega um número de sequência de 1 bit (0 ou 1), e o transmissor só envia o próximo quadro depois de receber a confirmação (ACK) do quadro atual. Um temporizador de retransmissão cobre o caso de perda do quadro ou do ACK.

O ABP resolve o problema de confiabilidade, mas é lento: o transmissor fica ocioso à espera de cada ACK. Considere, para estimar a eficiência, quadros de 1.000 bits, enlace de 50 kbps, atraso de propagação de 250 ms em cada sentido e ACKs curtos. O tempo de transmissão de um quadro é L/R = 1.000/50.000 = 0,02 s; como o RTT é aproximadamente 0,5 s, a eficiência do ABP sem perdas é (L/R)/(L/R + RTT) = 0,02/0,52 ≈ 3,85%, ou cerca de 1,92 kbps de vazão útil. A conta ignora o tamanho do ACK, cabeçalhos e perdas.

Desempenho

Janela deslizante: Go-Back-N e Selective Repeat

Para não desperdiçar o enlace esperando ACK a ACK, protocolos modernos usam pipelining: o transmissor pode ter até W quadros não confirmados "em voo" ao mesmo tempo — essa faixa de números de sequência permitidos é a janela deslizante.

Em ambos os casos, o tamanho máximo da janela é limitado pelo número de bits usados para o número de sequência: com n bits, Go-Back-N pode usar no máximo 2ⁿ − 1 quadros na janela para Go-Back-N, e no máximo 2ⁿ⁻¹ para Selective Repeat — do contrário o receptor pode confundir um quadro novo com uma retransmissão antiga.

Na prática

Do conceito à situação real

🌊 Cabos submarinos de verdade

Sistemas como o cabo 2Africa ou o EllaLink (que liga Brasil e Europa) usam DWDM para transportar dezenas de terabits por segundo em um único par de fibras — a mesma ideia da seção "Topo", em escala real. Consulte o Submarine Cable Map para explorar rotas e pontos de chegada. Parte significativa do tráfego local pode permanecer no país por meio de IXPs, como o IX.br, e de caches/CDNs próximos, sem cruzar um cabo submarino.

📶 A "última milha" no seu bairro

FTTH, HFC (cabo) e redes móveis 4G/5G são implementações diferentes da mesma ideia: o "Leito" da cachoeira, onde a rede do provedor finalmente encontra o seu roteador.

🧮 CRC no dia a dia

Quadros Ethernet carregam um FCS calculado com CRC-32, que a interface de rede verifica ao receber o quadro. Formatos como ZIP e PNG também definem verificações CRC para seus dados; isso detecta muitas corrupções acidentais, mas não é uma garantia de autenticidade nem de detecção de todo erro possível.

🔁 Janela deslizante no TCP

O TCP não é simplesmente Selective Repeat nem Go-Back-N. Ele numera bytes, normalmente confirma cumulativamente os bytes recebidos em ordem e pode armazenar dados fora de ordem; a opção SACK permite informar blocos recebidos fora de ordem. Por isso, sua recuperação combina características desses modelos.

Exemplos de código

Os trechos abaixo implementam, em Python, os principais mecanismos discutidos neste capítulo: detecção de erro por paridade, enquadramento por bit stuffing e uma simulação simplificada do Protocolo do Bit Alternante sobre um canal com perdas.

1. Detecção de erros: paridade, checksum e CRC

A detecção de erros acrescenta redundância ao quadro para que o receptor possa verificar se os bits recebidos são consistentes. A paridade escolhe um bit extra para que a quantidade de bits 1 seja par (ou ímpar): detecta qualquer quantidade ímpar de inversões, mas não detecta necessariamente uma quantidade par. Um checksum soma palavras de dados usando aritmética definida pelo protocolo e transmite o complemento da soma; é usado, por exemplo, no cabeçalho IPv4 e nos segmentos TCP/UDP (incluindo o pseudo cabeçalho definido por esses protocolos). Um CRC interpreta os bits como um polinômio sobre GF(2) e transmite o resto da divisão pelo polinômio gerador. CRCs detectam várias classes de erros em rajada, mas, como os demais, não corrigem erros nem garantem detectar toda corrupção possível. Ethernet usa CRC-32 no FCS.

Referências para conferência: Bonaventure, Computer Networking: Principles, Protocols and Practice, capítulo de enlace; RFC 1071 (checksum IP); RFC 9293 (TCP); IEEE 802.3 (FCS Ethernet).

Bit de paridade (exemplo)
def paridade_par(bits: str) -> str:
    """Recebe uma string de bits e devolve a string com 1 bit de paridade par ao final."""
    uns = bits.count("1")
    bit_extra = "0" if uns % 2 == 0 else "1"
    return bits + bit_extra

def verifica_paridade(bits_com_paridade: str) -> bool:
    """Retorna True se o número total de 1s for par (nenhum erro detectado)."""
    return bits_com_paridade.count("1") % 2 == 0

# Exemplo
quadro = "1001"
codificado = paridade_par(quadro)
print(codificado)                    # 10010
print(verifica_paridade(codificado)) # True

# Simulando um erro de transmissão em 1 bit
com_erro = "10011"
print(verifica_paridade(com_erro))   # False -> erro detectado
2. Enquadramento por bit stuffing
MARCADOR = "01111110"

def bit_stuffing(dados: str) -> str:
    """Insere um 0 após cada sequência de cinco 1s consecutivos."""
    saida = []
    contador_uns = 0
    for bit in dados:
        saida.append(bit)
        if bit == "1":
            contador_uns += 1
            if contador_uns == 5:
                saida.append("0")   # bit inserido (stuffing)
                contador_uns = 0
        else:
            contador_uns = 0
    return MARCADOR + "".join(saida) + MARCADOR

def remove_stuffing(quadro: str) -> str:
    """Remove o marcador e os bits inseridos, recuperando os dados originais."""
    corpo = quadro[len(MARCADOR):-len(MARCADOR)]
    saida = []
    contador_uns = 0
    i = 0
    while i < len(corpo):
        bit = corpo[i]
        saida.append(bit)
        if bit == "1":
            contador_uns += 1
            if contador_uns == 5:
                i += 1  # pula o bit inserido pelo transmissor
                contador_uns = 0
        else:
            contador_uns = 0
        i += 1
    return "".join(saida)

dados = "0110111111111111111110010"
quadro = bit_stuffing(dados)
print(quadro)
print(remove_stuffing(quadro) == dados)  # True
3. Simulação do Protocolo do Bit Alternante (ABP)
import random

def canal_com_perdas(prob_perda: float = 0.3) -> bool:
    """Simula um canal não confiável: retorna False se o quadro/ACK deve ser perdido."""
    return random.random() >= prob_perda

def alternating_bit_protocol(mensagens: list[str], prob_perda: float = 0.3):
    seq = 0
    for msg in mensagens:
        confirmado = False
        tentativa = 0
        while not confirmado:
            tentativa += 1
            print(f"[Host A] envia D({seq}, '{msg}')  (tentativa {tentativa})")

            if canal_com_perdas(prob_perda):
                print(f"[Host B] recebe D({seq}, '{msg}') -> entrega à aplicação, envia C(OK{seq})")
                if canal_com_perdas(prob_perda):
                    print(f"[Host A] recebe C(OK{seq}) -> quadro confirmado")
                    confirmado = True
                else:
                    print("[Host A] ACK perdido -> timer expira, retransmite")
            else:
                print("[Host A] quadro perdido no canal -> timer expira, retransmite")

        seq = 1 - seq  # alterna entre 0 e 1

alternating_bit_protocol(["a", "b", "c"])
