Capítulo 7

Modelos de referência

Bits, quadros, pacotes, segmentos e mensagens: os capítulos anteriores foram montando uma pilha de camadas, cada uma usando o serviço da de baixo. Este capítulo dá nome a essa organização, o modelo de referência de cinco camadas, e o compara com os modelos TCP/IP e OSI.

Apresentação

Uma pilha para organizar tudo

Com a complexidade crescente das redes, os pesquisadores dos anos 1970 propuseram modelos de referência para facilitar a descrição de protocolos e serviços. O mais influente foi o modelo OSI (Open Systems Interconnection), base da padronização de redes na ISO. O modelo usado pelo livro, e por este site, é uma versão simplificada do OSI, com cinco camadas.

Objetivos de aprendizagem

  • Nomear as cinco camadas do modelo de referência e a ordem entre elas.
  • Descrever o serviço de cada camada e as imperfeições do serviço da camada física.
  • Usar a terminologia do livro: bits, quadros, pacotes, segmentos e SDUs.
  • Explicar por que um roteador só vai até a camada de rede.
  • Comparar o modelo de cinco camadas com o TCP/IP (quatro) e o OSI (sete).

Antes de começar

Cada camada já apareceu antes: física e enlace no Capítulo 1, rede no Capítulo 2, aplicação no Capítulo 3 e transporte no Capítulo 4. O capítulo cobre a seção 2.7 do livro (pág. 115–119 do PDF).

Conceito 1

O modelo de referência de cinco camadas

1. Contextualização

Para descrever uma rede sem se perder nos detalhes, é útil dividi-la em camadas: cada uma oferece um serviço à camada de cima usando o serviço da camada de baixo. Que camadas são essas?

2. Explicação

O modelo do livro tem cinco camadas (Fig. 91). De cima para baixo: aplicação, transporte, rede, enlace e física, esta última ligada ao meio de transmissão físico. Os hosts têm as cinco camadas; os roteadores, que só encaminham pacotes, vão até a camada de rede (Fig. 94 e 95).

3. Visualização

Siga uma mensagem de A até B, camada por camada, passando por um roteador.

4. Prática

Como o livro descreve o seu modelo de cinco camadas?

5. Fixação

  • Cinco camadas: aplicação, transporte, rede, enlace e física.
  • Cada camada usa o serviço da de baixo e serve a de cima.
  • Hosts têm as cinco; roteadores vão até a rede.
Conceito 2

A camada física

1. Contextualização

Na base da pilha, dois dispositivos ligados diretamente por um meio físico trocam um sinal elétrico ou óptico. É o assunto do começo do Capítulo 1.

2. Explicação

O ponto importante é o serviço que a camada física oferece: em geral, um serviço não confiável de troca de bits, a unidade de informação dessa camada (Fig. 92). Ele não é confiável porque a camada física pode:

  • mudar o valor de um bit transmitido, por exemplo por interferência eletromagnética;
  • entregar ao receptor mais bits do que o emissor enviou;
  • entregar ao receptor menos bits do que o emissor enviou.

3. Visualização

4. Prática

Qual é a unidade de informação da camada física?

5. Fixação

  • Unidade: o bit.
  • Serviço não confiável: bits trocados, a mais ou a menos.
Conceito 3

A camada de enlace

1. Contextualização

Sobre o serviço imperfeito da camada física, a camada de enlace permite que dois hosts ligados diretamente troquem informação organizada, como os quadros do Capítulo 1.

2. Explicação

A unidade da camada de enlace é o quadro (frame), uma sequência finita de bits. As camadas de enlace variam bastante: algumas usam quadros de tamanho variável e outras de tamanho fixo; algumas oferecem serviço orientado a conexão e outras sem conexão; algumas entregam com confiabilidade e outras não dão garantias.

A Fig. 93 mostra duas entidades de enlace trocando quadros "diretamente", mas na prática a entidade da esquerda emite um Data.request para a camada física para cada bit do quadro. A física converte os bits num sinal; do outro lado, decodifica o sinal e emite os Data.indication correspondentes. Sem erros de transmissão, a entidade da direita recebe o quadro enviado.

4. Prática

Para enviar um quadro de 1000 bits, quantos Data.request a camada de enlace emite para a camada física?

5. Fixação

  • Unidade: o quadro, uma sequência finita de bits.
  • Liga hosts conectados diretamente; o serviço pode ou não ser confiável.
  • Usa a física bit a bit: um Data.request por bit.
Conceito 4

A camada de rede

1. Contextualização

A camada de enlace só liga hosts ligados diretamente. Muitas vezes, porém, os hosts que precisam conversar não estão no mesmo meio físico. Esse é o trabalho da camada de rede, o tema do Capítulo 2.

2. Explicação

As entidades de rede trocam pacotes: sequências finitas de bytes transportadas pela camada de enlace dentro de um ou mais quadros. Um pacote costuma levar informação sobre a origem e o destino e passa por vários dispositivos intermediários, os roteadores, no caminho (Fig. 94).

4. Prática

Como um pacote é transportado entre dois nós vizinhos?

5. Fixação

  • Unidade: o pacote, uma sequência finita de bytes, com origem e destino.
  • Liga hosts em meios diferentes, através de roteadores.
Conceito 5

A camada de transporte

1. Contextualização

A camada de rede faz os hosts se alcançarem, mas entre os mesmos dois hosts podem existir vários fluxos de comunicação, com necessidades diferentes: alguns exigem entrega confiável, outros não.

2. Explicação

Identificar um fluxo de comunicação entre dois hosts é tarefa da camada de transporte (o Capítulo 4). Suas entidades trocam segmentos, sequências finitas de bytes transportadas dentro de um ou mais pacotes; a entidade de transporte entrega segmentos (ou partes deles) à camada de rede como Data.request (Fig. 95). Na Internet, as camadas de transporte mais usadas são o TCP, um serviço confiável, orientado a conexão e de fluxo de bytes, e o UDP, um serviço não confiável e sem conexão.

4. Prática

Qual é a tarefa da camada de transporte segundo o livro?

Qual protocolo de transporte oferece um serviço sem conexão e não confiável?

5. Fixação

  • Unidade: o segmento, transportado em um ou mais pacotes.
  • Distingue fluxos entre os mesmos hosts.
  • TCP: confiável, com conexão, fluxo de bytes. UDP: não confiável, sem conexão.
Conceito 6

A camada de aplicação e a terminologia

1. Contextualização

No topo da pilha estão as aplicações, como as do Capítulo 3. Com cinco camadas trocando informação, convém ter um nome para a unidade de cada uma.

2. Explicação

A camada de aplicação inclui todos os mecanismos e estruturas de dados de que as aplicações precisam. A informação trocada entre duas entidades de aplicação é chamada de ADU (Application Data Unit) ou, de forma genérica, SDU (Service Data Unit) (Fig. 96). Conceito 7

Os modelos TCP/IP e OSI

1. Contextualização

Dois modelos de referência fizeram sucesso na comunidade de redes: o TCP/IP e o OSI. Como eles se comparam com o modelo de cinco camadas?

2. Explicação

TCP/IP: ao contrário do OSI, a comunidade TCP/IP não se esforçou para definir um modelo detalhado; os objetivos da arquitetura da Internet só foram documentados depois que o TCP/IP já estava em uso. A RFC 1122, que define os requisitos dos hosts da Internet, cita quatro camadas: aplicação, transporte, Internet (equivalente à rede do modelo do livro) e enlace (link), que junta as funções das camadas física e de enlace. Fora essa diferença nas camadas de baixo, o TCP/IP é muito próximo do modelo de cinco camadas.

OSI: tem sete camadas (Fig. 97). As quatro de baixo são parecidas com as do modelo do livro; a camada de aplicação é refinada em três:

  • Sessão: organiza e sincroniza o diálogo entre as entidades de apresentação. Enquanto o transporte lida com a falta de confiabilidade da rede, a sessão esconde as falhas das conexões de transporte: estabelece a conexão de sessão, mantém a troca em ordem (inclusive após uma liberação abrupta da conexão de transporte) e a encerra de forma ordenada.
  • Apresentação: lida com as diferentes formas de representar a informação nos computadores (inteiros de 32 ou 64 bits, números de ponto flutuante, códigos de caracteres, registros estruturados), oferecendo uma representação comum dos dados. A notação ASN.1 foi criada para ela e ainda é usada por alguns protocolos.
  • Aplicação: o que não cabe na sessão nem na apresentação; no OSI, ela é dividida em vários elementos de serviço genéricos.

Complemento
O livro diz que o Unicode representa "mais de 100 000 caracteres" e que ainda não é o padrão universal de troca de texto. As versões atuais do Unicode já passam de 150 000 caracteres, e o UTF-8 se tornou a codificação dominante na Web (Wikipedia: Unicode).

4. Prática

A camada de enlace (link) do TCP/IP corresponde a quais camadas do modelo do livro?

Em que camada do OSI fica a notação ASN.1?

5. Fixação

  • TCP/IP (RFC 1122): aplicação, transporte, Internet e enlace (física + enlace).
  • OSI: sete camadas; a aplicação do livro vira aplicação, apresentação e sessão.
  • O modelo do livro fica entre os dois.
Pratique

Exercícios graduados

  1. Aquecimento: ordene de baixo para cima: segmento, bit, SDU, pacote, quadro.
    Ver solução

    Bit (física), quadro (enlace), pacote (rede), segmento (transporte) e SDU (aplicação).

  2. Aquecimento: um host A envia a B por dois roteadores. Quantas vezes a mensagem passa por uma camada de rede?
    Ver solução

    Quatro: em A, nos dois roteadores e em B. A camada de transporte só é usada em A e em B.

  3. Intermediário: uma SDU de 1000 bytes ganha cabeçalhos de 20 bytes no transporte, 20 na rede e 18 no enlace. Quantos bits a camada física transmite?
    Ver solução

    1000 + 20 + 20 + 18 = 1058 bytes, ou 8464 bits, e a camada de enlace emite 8464 Data.request.

  4. Intermediário: a camada física entregou 01010010 quando o emissor enviou 0101010. O que aconteceu?
    Ver solução

    Chegaram 8 bits para 7 enviados: a camada física entregou bits a mais (um bit 0 a mais depois da quinta posição).

  5. Desafio: uma aplicação precisa retomar uma transferência longa depois que a conexão de transporte cai, sem recomeçar do zero. Em que camada do OSI esse mecanismo ficaria? E no modelo do livro?
    Ver solução

    No OSI, na camada de sessão, que esconde as falhas das conexões de transporte. No modelo de cinco camadas (e no TCP/IP), dentro da própria camada de aplicação.

Exemplos de código

Três trechos em Python que rodam no navegador. Edite, execute e resolva os desafios de cada bloco.

1. Encapsulamento e desencapsulamento

# Cada camada acrescenta o seu cabeçalho na frente do que recebeu de cima.
CABECALHOS = [
    ("transporte", b"[SEG porta=80]"),
    ("rede",       b"[PKT A->B]"),
    ("enlace",     b"[QUADRO]"),
]

def desce(sdu):
    unidade = sdu
    for camada, cab in CABECALHOS:
        unidade = cab + unidade
        print(f"{camada:>10}: {unidade}")
    return unidade

def sobe(quadro):
    unidade = quadro
    for camada, cab in reversed(CABECALHOS):
        assert unidade.startswith(cab), f"cabeçalho de {camada} não confere"
        unidade = unidade[len(cab):]
        print(f"{camada:>10} entrega: {unidade}")
    return unidade

quadro = desce(b"GET /index.html")
bits = "".join(f"{byte:08b}" for byte in quadro)
print(f"    física: {len(bits)} bits, começando por {bits[:24]}...")
print("Recebido pela aplicação:", sobe(quadro))

2. Uma camada física não confiável

import random

def canal_fisico(bits, rnd):
    """Camada física não confiável: troca, insere ou remove um bit (livro, pág. 115)."""
    i = rnd.randrange(len(bits))
    tipo = rnd.choice(["troca", "insere", "remove"])
    if tipo == "troca":
        return bits[:i] + ("1" if bits[i] == "0" else "0") + bits[i + 1:]
    if tipo == "insere":
        return bits[:i] + rnd.choice("01") + bits[i:]
    return bits[:i] + bits[i + 1:]

def diagnostica(enviado, recebido):
    if len(recebido) > len(enviado):
        return "bits a mais"
    if len(recebido) < len(enviado):
        return "bits a menos"
    if recebido != enviado:
        return "bit trocado"
    return "sem erro"

rnd = random.Random(4)
enviado = "01010010100010101001010"       # a sequência da Fig. 92 do livro
for _ in range(5):
    recebido = canal_fisico(enviado, rnd)
    print(f"{recebido:<25} -> {diagnostica(enviado, recebido)}")

3. Três modelos lado a lado

CINCO = ["Aplicação", "Transporte", "Rede", "Enlace", "Física"]
OSI = ["Aplicação", "Apresentação", "Sessão", "Transporte", "Rede", "Enlace", "Física"]
TCPIP = ["Aplicação", "Transporte", "Internet", "Enlace (link)"]

# Para cada camada do modelo de 5 camadas: camadas equivalentes no OSI e no TCP/IP
CORRESPONDE = {
    "Aplicação":  (["Aplicação", "Apresentação", "Sessão"], "Aplicação"),
    "Transporte": (["Transporte"], "Transporte"),
    "Rede":       (["Rede"], "Internet"),
    "Enlace":     (["Enlace"], "Enlace (link)"),
    "Física":     (["Física"], "Enlace (link)"),
}
UNIDADE = {"Aplicação": "SDU", "Transporte": "segmento", "Rede": "pacote", "Enlace": "quadro", "Física": "bit"}

print(f"{'5 camadas':<11} {'unidade':<9} {'OSI':<36} TCP/IP")
for camada in CINCO:
    osi, tcpip = CORRESPONDE[camada]
    print(f"{camada:<11} {UNIDADE[camada]:<9} {' + '.join(osi):<36} {tcpip}")
print(f"OSI: {len(OSI)} camadas · 5 camadas · TCP/IP: {len(TCPIP)} camadas")
